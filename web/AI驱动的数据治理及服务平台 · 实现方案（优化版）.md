# AI驱动的数据治理及服务平台 · 实现方案（优化版）

## 一、产品定位

不做"大而全的数据中台"，解决两个核心问题：**数据怎么快速接进来、脏数据怎么快速变成可用数据**，并以数据服务方式安全地开放出去。

核心理念：用户给数据、URL、接口文档或一句话需求，**AI 负责分析、配置、执行、检查和修复建议，确定性引擎负责真正执行**。

整体链路：

```
数据源 → AI接入 → 数据画像 → AI清洗 → AI验证 → 标准数据 → 数据服务（API/MQ/音视频）→ 消费方
```

## 二、总体架构

```
┌─────────────────────────────────────────────────────┐
│ 门户：数据工作区 + Copilot 对话入口 + 管理后台        │
├─────────────────────────────────────────────────────┤
│ AI 中台：Data Engineer Agent（统一调度）              │
│   ├─ 接入Agent / 数据理解Agent / 清洗Agent            │
│   └─ 验证Agent / 运维Agent                            │
│   约束：所有 Agent 输出 → DSL 白名单校验 → 执行引擎   │
├─────────────────────────────────────────────────────┤
│ 执行引擎：Connector框架 / SQL / Spark / Flink / Python │
├─────────────────────────────────────────────────────┤
│ 存储：湖仓（Iceberg + MinIO）原始层→标准层→服务层     │
│       元数据与血缘（OpenMetadata）                    │
├─────────────────────────────────────────────────────┤
│ 服务网关：应用注册/Token/限流/配额/权限/脱敏/审计      │
└─────────────────────────────────────────────────────┘
```

关键设计原则：**AI 只做规划与建议，不直接执行**。所有 AI 产出统一编译为 DSL（可预览、可审批、可回滚、可审计、可复用），由规则引擎翻译成 SQL/Spark/Flink 任务执行。

## 三、数据采集（接入Agent）

插件化 Connector 框架，新增数据源只需开发插件。AI 在此层的价值：**用户不懂 CDC、主键、offset、watermark 也能完成接入**。

| 数据源 | 接入方式 | AI 能力 |
|---|---|---|
| DB（MySQL/Oracle/PG/达梦等） | CDC（Debezium）增量 + JDBC 全量 | 数据库体检：扫描表结构、识别主键/增量字段/表关系/数据量/敏感字段，推荐全量/增量/CDC 策略，生成任务待用户确认 |
| Excel/CSV | 文件上传 | 识别多Sheet/真表头/合并单元格/空值符号（"-"、"/"），推断类型，自动完成宽表转长表等结构规整 |
| URL网页 | 内置可配置爬虫（列表/详情/翻页/去重） | 给 URL 自动识别页面结构、抽取字段、生成爬取规则；页面结构变化时自动重新分析并**建议**修复 Selector（人工确认后恢复任务） |
| API | HTTP轮询/Webhook | 直接读 Swagger/OpenAPI/PDF/Word 接口文档，自动识别鉴权、分页、时间参数，生成请求并测试调用 |
| Kafka/MQTT | 订阅接入 | 抽样消息→判断 JSON/Avro/ProtoBuf→推断 Schema→识别 Schema 漂移→建议事件时间与 Watermark |
| 音视频（RTSP/GB28181/文件） | 流接入 + 文件上传 | 聚焦"非结构化→结构化"：ASR 语音转写（含说话人分离、时间戳）；视频抽帧 + OCR + 目标/场景/事件识别；统一输出"原始文件 + 结构化JSON" |

任务调度支持全量/增量/实时三种模式，断点续传、失败重试、采集监控（流量/延迟/失败率）。

## 四、数据清洗（理解Agent + 清洗Agent + 验证Agent）

平台最核心模块，三步闭环：

**① 自动理解数据（Profile）**：任何数据进入后自动探查——缺失率、重复率、格式异常、值分布、枚举值不一致（如"黑龙江/黑龍江/HLJ"），输出数据质量问题清单。用户不需要告诉平台"哪里脏"。

**② 自动生成清洗方案**：针对每个问题给出规则建议和**预计影响行数**，用户确认后执行。内置规则库：去重、空值处理、格式标准化（日期/手机号/身份证）、值域校验、异常值剔除、字段映射拆分合并、正则替换。

**③ 自然语言修改规则**：

```
用户："客户姓名一样、手机号一样视为同一客户，保留最新记录。"
→ DSL：
operation: deduplicate
fields: [name, mobile]
keep: {order_by: update_time, order: desc, row: first}
```

**④ 清洗验证（关键差异化）**：清洗后自动对比清洗前后——记录数、NULL 率、重复率、分布、字段类型、业务指标变化。发现异常（如"清洗后营收总额减少17%，疑似去重规则过严"）时**主动阻止发布**并提示原因。不只帮用户写规则，更帮用户判断规则有没有把数据洗坏。

流程保证：原始数据贴源层不动 → 规则管道 → 二次数据写入标准层；支持清洗前后对比预览、规则版本管理、管道模板复用。

## 五、数据服务（服务网关）

对标主流开放平台的应用注册机制：

- **应用注册**：开发者注册应用 → 颁发 AppKey/AppSecret → OAuth2/AK-SK 换取 Token（JWT，支持过期刷新）→ 按应用授权数据资源范围，未注册无 Token 不可调用。
- **服务形态**：
  - API：数据表一键发布为 RESTful API（参数化查询/自定义 SQL），自动生成 OpenAPI 文档；
  - 消息订阅：清洗结果/数据变更推送至 Kafka/MQTT Topic，应用订阅消费；
  - 音视频：结构化结果走 API，流数据以 RTSP/WebSocket 转发。
- **安全控制（网关统一实现）**：
  - 限流（QPS/并发）、配额（日调用量）、超阈值熔断；
  - IP 黑白名单、行列级权限、字段级脱敏（敏感字段自动识别 PII）；
  - 全量调用审计日志 + 用量报表。

## 六、数据预览

- 表格在线预览（分页/筛选/排序）、清洗前后对比视图；
- 音视频在线播放 + 结构化结果（转写文本、识别目标）叠加展示；
- 数据血缘可视化：来源 → 清洗管道 → 下游服务，支持质量问题溯源。

## 七、Copilot 交互入口

主界面 = 数据预览 + AI 数据工程助手对话框。用户直接说：

> "把这个 Excel 整理一下" / "这个接口每天同步一次" / "为什么昨天任务失败了" / "清洗成可以给大模型训练的数据"

实现 **Chat with Data Engineering**。

## 八、运维Agent（异常处理）

任务失败 → 读取日志 → 判断原因 → **给出修复建议，人工确认后执行** → 重新运行。

覆盖典型问题：Excel 字段变化、API 增字段、库表字段类型变化、网页改版、JSON Schema 漂移、Token 过期、编码/时间格式异常。

> 说明：原稿"AI 自动修复、自动恢复任务"工程风险高，建议一期降级为"AI 诊断 + 人确认"，验证成熟后再逐步提高自动化等级。

## 九、Agent 体系收敛

只保留 5 个 Agent，由 Data Engineer Agent 统一调度：

| Agent | 职责 |
|---|---|
| 接入Agent | 自动创建采集任务 |
| 数据理解Agent | Schema、语义、Profile 分析 |
| 清洗Agent | 设计和生成清洗管道（DSL） |
| 验证Agent | 判断清洗结果是否正确 |
| 运维Agent | 发现并诊断失败任务 |

## 十、工程约束（AI 可靠性）

1. **DSL 白名单**：所有 Agent 产出必须编译为 DSL，经校验后执行，杜绝 LLM 直接生成并运行 SQL/代码；
2. **人在回路**：任务创建、规则变更、对外发布、失败修复均需用户确认；
3. **可回滚**：清洗不落原始层，规则版本化，随时回退；
4. **成本控制**：Profile 采样分析、LLM 调用走统一网关（限流、缓存、小模型优先）。

## 十一、实施路径

**一期（MVP，2–3 个月）**：
- 输入：DB、Excel/CSV、API、URL；
- 核心闭环：自动理解数据 → 发现脏数据 → 推荐清洗方案 → 自然语言改规则 → 执行 → 验证；
- 输出：Excel/CSV/DB表/API；
- 服务网关基础版：应用注册 + Token + QPS 限流。

**二期（3–4 个月）**：
- Kafka/MQTT 接入、音视频接入与 ASR/视频结构化；
- 消息订阅服务、配额量控、行列权限与脱敏；
- 清洗验证Agent 完整版、血缘可视化。

**三期**：
- 数据画像增强与规则智能推荐、NL2SQL 查数；
- 敏感数据自动识别分级、质量评分体系；
- 运维Agent 自动化等级提升（半自动→自动修复）。

## 十二、核心卖点

不宣传"AI赋能数据治理平台"（太泛），直接讲：

> **把数据工程师 80% 的重复工作交给 AI —— 一个会接数据、懂数据、会清洗、会排错的数据工程师。**

## 十三、非功能指标

- 实时流接入延迟 < 5s；服务网关 P99 < 200ms；
- 多租户隔离，数据落库加密，全链路操作审计；
- 各层（采集/引擎/网关）水平扩容。
