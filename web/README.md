# KData Studio · 数据采集与智能清洗平台

依据《AI驱动的数据采集与智能清洗平台设计方案》重新开发的前端工程。以”接入 → 解析 → 清洗与预览 → 确认入库”为主线，保留数据任务、清洗规则、数据服务三个主菜单。来源选择与配置统一放在创建任务中，数据服务管理清洗成果。图片 / 音频 / 视频三个来源走独立的媒体清洗工作台（见下文）。

采用 React 19、TypeScript、Vite 和 Lucide 图标。登录、工作区持久化、数据库/API 连接器、图片/音频/视频清洗均依赖仓库根目录的 `bff/` 服务端；仅 Excel/CSV 本地文件解析在登录后完全本地执行，不需要额外配置。

## 启动与构建

使用 Node.js 22.12+。

```bash
npm install
npm run dev
```

打开终端显示的本地地址，默认 http://localhost:5173 。

```bash
npm run build    # 类型检查及生产构建，产物输出至 dist/
npm run preview # 预览生产构建
npm test        # 清洗、演示入库与数据服务业务测试
npm run format  # 格式化源代码
```

使用 hash 路由，静态部署无需服务端路由重写。部署到子目录时配置 `vite.config.ts` 的 `base`。

## 页面与功能

| 页面       | 功能                                                                           |
| ---------- | ------------------------------------------------------------------------------ |
| 数据任务   | 创建任务、来源选择、状态筛选、搜索、分页、进入工作台                           |
| 数据工作台 | Excel 式表格与右侧 AI 副驾驶；原始、清洗后、异常、执行记录四种视图             |
| 清洗规则   | 30 条系统规则、11 个分类；个人规则、企业规则、清洗模板；添加到任务、复制与保存 |
| 数据服务   | 最新清洗成果、状态数量、搜索分页、CSV / JSON 导出、服务字段配置与接口文档      |

工作台支持冻结表头与行号、字段统计、语义类型与显示名称修改、拖动或键盘调整列宽、隐藏列、排序、搜索、多条件筛选、分页和前 100 行抽样。单元格详情展示完整内容与原始值；修改单元格为黄色，删除记录在原始视图为红色。

所有页面省去全局顶部导航，窄屏下可通过页面标题旁的菜单按钮打开侧栏。工作台的分页、行列统计和变更图例整合在表格顶部；单元格详情与内容栏合并，不再占用底部数据空间。AI 副驾驶采用紧凑标题、评分和问题列表，中间内容区与上下操作区通过底色区分。桌面端可拖动表格与 AI 副驾驶之间的分隔线调整宽度，也可聚焦分隔线后用键盘方向键微调；双击分隔线或按 Enter 恢复默认宽度，调整结果会保存在当前浏览器。

AI 副驾驶有数据质量、一键清洗、清洗规则、AI 对话四个标签。规则可以选择、配置、排序、移除、存为模板。执行前按实际数据计算修改、删除、异常及保留行数，显示质量评分与业务指标影响，确认后生成新的执行记录。

## 统一状态说明

数据处理、入库、服务配置分别表示不同环节，页面标签、筛选和使用指南共用 `src/lib/status.ts` 中的定义。

| 环节     | 状态     | 含义                                     |
| -------- | -------- | ---------------------------------------- |
| 数据处理 | 待清洗   | 已解析，尚未执行清洗                     |
| 数据处理 | 清洗完成 | 最新结果非空且校验通过，可用于数据服务   |
| 数据处理 | 校验异常 | 最新结果校验未通过或为空，仅在任务中处理 |
| 入库     | 待入库   | 清洗完成，最新结果尚未确认写入目标表     |
| 入库     | 已入库   | 最新清洗版本已写入本地演示目标表         |
| 服务配置 | 待配置   | 清洗完成，尚未保存服务配置               |
| 服务配置 | 待部署   | 配置已保存且对应最新结果，接口尚未上线   |
| 服务配置 | 待更新   | 清洗版本或字段发生变化，需确认更新配置   |

已入库不改变“清洗完成”的处理状态。重新清洗后根据最新结果重新计算处理状态、入库状态和服务配置状态。校验异常时不会回退展示旧版清洗结果。原始数据、异常集和历史仍保留在任务工作台中。使用指南同时提供以上说明；原工作空间卡片已移除，底部“工作区信息”仍可查看信息和导出备份。

## 推荐体验路径

1. 在数据任务中打开“客户数据标准化”。
2. 点击字段名称查看统计，或点击右侧质量问题定位相关记录。
3. 点击“一键智能清洗”，核对影响预览，再点击“开始清洗”。
4. 样例 50 行使用默认方案：保留 46 行、删除 2 条完全重复记录、2 行进入异常集；保留记录中有 41 行被修改。
5. 查看黄色修改单元格、异常原因及清洗报告。原始 50 行始终保留。
6. 点击“确认入库”，配置目标库表、写入方式、字段映射和类型，再检查生成的 DDL，最后确认写入演示表。
7. 在“数据服务”预览最新清洗结果，导出 CSV / JSON；点击“配置服务”选择输出字段、接口标识和分页大小，保存并导出待部署的服务配置。
8. 在 AI 对话中输入“客户名称一样且手机号后8位一样，保留最新记录”，保存为个人规则，再到清洗规则库复用。

`examples/客户数据示例.csv` 可用于上传体验。`examples/验证拦截示例.csv` 包含金额分别为 100 / 200 的同名同号记录：上传后通过 AI 加入”姓名和手机号一样，保留更新时间最新的记录”，执行后金额减少 33.3%，应提示业务异常并禁用入库。

另有一个”黑龙江省地市经济与人口指标”样例任务（真实数据，来源见 `src/data/heilongjiang.ts` 顶部注释），故意保留了地区别名不统一（黑龙江/黑龍江/HLJ/黑龙江省）和一条重复记录，适合演示”地区别名”系统规则和去重；同一份数据也灌进了根 `README.md` 里说明的 `demo-db` 演示数据库，可以用来演示”数据库”连接器的真实连接与抓取。

## 本地处理与演示边界

**真实本地执行**：CSV / XLSX 解析、数据画像、30 条规则处理、异常分流、变更对照、执行历史、导出，以及浏览器内数据表的新建、覆盖、追加、按主键更新。

**真实接入**：数据库（MySQL/PostgreSQL）、API 连接器会真实连接、测试、抓取数据（详见根 `README.md`”数据库 / API 连接器”一节），只执行只读查询，连接凭证加密存储；AI 对话本地正则优先匹配常见说法，未命中时由火山方舟大模型理解并从规则目录里选规则（模型只能”选”不能”编”新操作，选出来的规则和参数键名都会再校验一遍才会生效，不会执行任意代码）。

**前端模拟**：URL / 网页在创建任务中保存地址并载入样例，不发起真实抓取（通用网页爬虫工作量大、易碎，暂不做）；入库写入本地浏览器，不连接真实数据库；对外数据服务接口尚未真正开放。

**图片 / 音频 / 视频清洗**：与表格任务是两条独立链路，走独立的媒体工作台，不经过表格清洗规则、入库与数据服务。依赖仓库根目录的 `bff/` 服务端（基于火山引擎 API）：图片输出结构化字段（可编辑）+ 全文 OCR + 摘要标签；音频输出分说话人转写 + 摘要要点待办；视频边播放边给出实时字幕与画面事件，结束后生成章节与整片摘要。任务提交后在服务端后台任务槽持续处理，与浏览器连接生命周期解耦；同一时间每种类型最多处理一个任务。结果缓存在当前工作区，可在”数据任务”页面的”媒体任务”列表中随时回看。`bff/` 未运行或未配置密钥时，这三个入口会请求失败并提示，不影响表格数据清洗。

- 文件最大 5 MB / 10,000 行。CSV 使用 UTF-8，XLSX 读取首个工作表；在前 10 行选择非空单元格最多的候选表头，表头必须非空且唯一。自动判断不合适时先整理源文件。
- 原始数据只读保存，每次执行从原始数据生成新结果，历史记录保留当次规则、处理结果和异常原因。
- 空字符串、`-`、`/`、`NA`、`N/A`、`null` 可统一为真正的 `null`；不会伪造缺失手机号。联合去重时，缺少身份字段的记录不会合并。
- 内置规则覆盖空值填充/分流、整行和联合去重、字符串、金额单位、日期、格式校验、省份别名、字典、范围校验、过滤、脱敏。复杂地址拆分、权威身份校验、任意语义或代码生成尚未实现。
- 金额类字段合计减少超过 10%，或清洗后为空，会阻止入库。评分衡量当前规则覆盖的数据格式，不能证明业务正确；阈值暂在代码内定义。
- 追加和增量更新检查目标列名结构；更新主键必须非空且唯一。真实数据库类型约束、事务与权限需要后端落实。
- 数据服务每个任务只展示最近一次清洗结果；原始数据、异常集和历史记录仍在任务工作台中。仅最新结果非空且校验通过的任务进入服务清单。未清洗、空结果及校验异常都不展示，已有服务配置也不能使异常任务继续显示；重新清洗通过后会重新进入清单。
- 服务名称、唯一接口标识、输出字段和每页条数保存在工作区；敏感字段默认不选。服务配置关联具体清洗版本，再次清洗后标记“待更新”，需确认更新配置。接口文档与 JSON 配置文件包含分页响应示例，只读取所选版本的清洗数据。
- 数据服务接口尚未部署，保存配置后状态为“待部署”，不会发起网络调用或生成已上线的 API。实际接口、鉴权、访问授权与部署由后续后端实现。
- 旧地址 `#data` 自动转到 `#services`，`#connections` 转到 `#tasks`；保留旧工作区的任务、清洗结果及本地入库数据。独立的数据接入页面和配置管理功能已移除。
- 当前工作区保存在 `localStorage` 的 `kdata.studio.v2` 键；不覆盖旧版本存储。浏览器空间不足时显示提示，可从工作区信息导出 JSON 快照；快照导入暂未实现。
- 单元格数据与规则保存在当前浏览器。任务、规则和模板的多人共享、权限审批、定时采集和服务端审计需要后续后端支持。

## 工程结构

```text
src/
  App.tsx                    路由、工作区状态、全局入口
  pages/
    Tasks.tsx                数据任务首页（表格任务 + 媒体任务列表）
    Workbench.tsx            表格任务主流程与工作台
    MediaWorkbench.tsx       图片/音频/视频清洗工作台
    RuleLibrary.tsx          系统 / 个人 / 企业 / 模板
    DataServices.tsx         清洗成果、服务配置与接口文档
  components/
    Sheet.tsx                表格、筛选、字段统计与执行记录
    Copilot.tsx              质量分析、清洗方案、AI 对话
    ResizableWorkspace.tsx   可调宽度的表格与副驾驶布局
    CreateTask.tsx           来源向导、文件解析与媒体任务提交
    RuleEditor.tsx           规则字段与参数配置
    RulePicker.tsx           系统规则选择器
    PlanPreview.tsx          规则影响预览与确认执行
    ImportDialog.tsx         入库映射与最后确认
    UI.tsx                   弹窗、状态与公共控件
    TableHeading.tsx         共用表头图标与字段类型图标
    media/
      ImageResultView.tsx    结构化字段、明细行、OCR 全文
      AudioResultView.tsx    转写、摘要、要点待办
      VideoResultView.tsx    字幕跟随播放、画面事件、章节摘要
  data/
    rules.ts                 可执行规则目录
    seed.ts                  初始工作区与样例数据
  hooks/
    usePacedReveal.ts        列表按固定节奏逐条释放（视频字幕/事件用）
  lib/
    types.ts                 领域类型（含 MediaTask）
    engine.ts                纯函数画像、规则、验证与导出
    warehouse.ts             演示入库及目标检查
    services.ts              清洗成果目录、服务配置校验与响应示例
    status.ts                全平台统一处理、入库、服务配置状态
    services.test.ts         服务状态、版本、字段、分页与兼容性测试
    storage.ts                本地持久化
    engine.test.ts           业务测试
    media.ts                 图片/音频/视频清洗的数据契约与 bff 客户端
  styles.css                 桌面与小屏样式
```

后续接入后端可沿用 `DataTask`、`Rule`、`Run`、`Destination` 类型，将来源采集、自然语言解析、清洗执行与入库确认替换为 API 调用。服务端需独立执行参数校验、数据验证、权限控制、任务调度和审计。
